# BackFlow HΦ oracle fixture

This fixture freezes exact ground-state energies for the four-site, half-filled
Hubbard ring (`t=1`, `U=4`, `Ncond=4`, `2Sz=0`).  The oracle is HΦ 3.5.2; no
mVMC implementation result and no separately written exact-diagonalization
solver is used to define the expected energies.

`manifest.json` records the HΦ release tag and commit, the producing binary
checksum, every checked-in input/output checksum, the translation sector, and
the mVMC optimization acceptance rule.  The PBC case projects onto `K=pi`; the
APBC case projects onto `K=0` and uses the boundary-crossing signs generated by
HΦ's `phase0=180` convention.  The corresponding mVMC fixture expresses those
same signs through `QPTransSgn`.

Normal CTest runs do not require HΦ.  They verify the frozen files and sector
record, then compare mVMC optimization results with the energy stored here.
The large binary HΦ eigenvectors are intentionally not checked in; their
SHA-256 digests and the derived translation checks are frozen in
`manifest.json` and `sector_check.txt`.

## Reproduction

Use the HΦ 3.5.2 binary recorded in `manifest.json` and run each case in a
fresh scratch directory so that generated files do not modify the fixture:

```sh
fixture=test/python/data/BackFlow_HPhi_Chain_L4
scratch=$(mktemp -d)
cp "$fixture/pbc/"*.def "$fixture/pbc/stan.in" "$scratch/"
cd "$scratch"
"$HPHI" -s stan.in
```

For APBC, replace `pbc` with `apbc`.  From the build-tree
`test/python` directory, verify the generated eigenvector sector with:

```sh
python hphi_sector_check.py \
  /path/to/scratch/output/zvo_eigenvec_0_rank_0.dat \
  --nsite 4 --nup 2 --ndown 2 --expected-real -1

python hphi_sector_check.py \
  /path/to/apbc-scratch/output/zvo_eigenvec_0_rank_0.dat \
  --nsite 4 --nup 2 --ndown 2 --antiperiodic --expected-real 1
```

The checker only parses the HΦ eigenvector and applies the documented lattice
translation in HΦ's fixed-`Sz` basis; it does not diagonalize a Hamiltonian.
If a deliberate oracle regeneration changes any frozen file, review the HΦ
version/commit, energy, sector residual, and eigenvector digest first, then
update the per-file hashes and acceptance provenance in `manifest.json` in the
same change.
